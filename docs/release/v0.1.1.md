# Android DJ Tools v0.1.1

Release date: 2026-09-17

`v0.1.1` is a patch release that integrates and hardens the post-`v0.1.0` preparation, offline/sync, analysis-advisory, parity, and CI qualification work while preserving Sample Lib as canonical metadata authority.

## Highlights

- Cue/loop and beat-grid preparation are integrated, including fail-closed half/double BPM correction and locale-stable BPM editing.
- Offline mutation journal, conflict handling, download/cache foundations, direct Sample Lib transport, and receipt semantics are exercised through deterministic qualification, including process recreation, exact-ID retry, offline/unavailable/ambiguous delivery recovery, and authoritative canonical reconciliation.
- Analysis candidates for BPM, musical key, and related-track intelligence stay advisory until explicit user acceptance is journaled and an authoritative receipt applies the mutation.
- DJXML remains an exchange projection behind Sample Lib. Canonical asset and playlist identities must come from Sample Lib; path, filename, XML track number, and list position are never promoted into Android authority.
- CI renders the five primary UI surfaces on Android 15 / Pixel 7 Pro and validates the emitted PNGs before uploading them.
- Release CI now verifies that the app version, changelog entry, and pushed `v*` tag agree, and APK artifact naming derives from the app version.

## Release gate

The tag is publishable only after the final integrated tree passes (or, for hosted CI, after the pushed release-preparation commit produces the required green run):

1. release metadata/tag consistency;
2. sync protocol/fake-server tests;
3. real Sample Lib DJXML adapter and playlist-authority qualification;
4. Android JVM unit tests;
5. instrumentation-test source compilation;
6. Android lint;
7. debug APK assembly;
8. `git diff --check`;
9. APK SHA-256 capture and smoke inspection;
10. independent workflow review of the release-critical implementation packet.

## Evidence boundaries

The release distinguishes four evidence classes instead of treating them as interchangeable:

- **fixture/fake server:** deterministic protocol and failure-mode qualification;
- **real Sample Lib:** direct adapter/API qualification against the current local Sample Lib authority implementation;
- **CI emulator:** Android 15 / Pixel 7 Pro instrumentation and screenshot rendering when the GitHub Actions job completes;
- **local physical device:** not claimed unless the release evidence names an actually exercised device.

Physical-device TalkBack, lock-screen/notification/Bluetooth/audio-focus, and sustained frame-time/jank behavior therefore remain outside the local release claim unless separately recorded.

The generated parity matrix is intentionally not promoted into a full-parity claim for this patch. The refreshed 2026-09-17 ledger covers all 87 required stories as 49 pass, 13 partial, and 25 blocked, with 0 missing and 0 fail. Real Sample Lib qualification is green, while the remaining red evidence is primarily device-tier work because the healthy SDK adb reports zero attached targets. The release-critical Lane B implementation packet has been independently reviewed and approved. Hosted API-35 CI remains a tag gate; the separate exact-snapshot parity review remains a full-product-parity qualification gate.

AGP 8.5.2 still warns that compileSdk 35 is newer than its certified compileSdk 34 range. The warning is intentionally visible; a green release requires the build/test matrix to pass despite it.

## Artifact

The release artifact is the unsigned debug APK produced by `:app:assembleDebug` at `app/build/outputs/apk/debug/app-debug.apk`. It is intended for dogfooding and development, not Play Store distribution.

GitHub Actions uploads the APK using a version-derived workflow artifact name (`androidjtools-v0.1.1-debug-apk` for this release). This release-preparation flow does not publish a GitHub Release object; that would require separate authorization.

Release evidence is recorded under `evidence/release/` and includes the exact commands, revision, artifact hash, and publication state.
